Patrones de Diseño

Patrones implementados en la arquitectura del sistema

Repository Pattern

Abstrae el acceso a datos detrás de interfaces. Cada entidad tiene su repositorio con operaciones CRUD estándar.

public interface IGenericRepository<T>
{
  IEnumerable<T> List();
  T Find(int id);
  RequestStatus Insert(T item);
  RequestStatus Update(T item);
  RequestStatus Delete(int id);
}

Service Layer

Encapsula la lógica de negocio. Los servicios coordinan repositorios y transforman datos con AutoMapper.

public class MascotaService
{
  // Repository + AutoMapper injected
  private readonly MascotaRepository _repo;
  private readonly IMapper _mapper;

  ServiceResult ObtenerMascotas() { ... }
  ServiceResult CrearMascota(VM) { ... }
}

ViewModel Pattern

Separa las entidades de BD de los modelos de la UI. Cada entidad tiene variantes: List, Form, Details y Dropdown.

MascotaListViewModel → DataTable
MascotaFormViewModel → Formularios
MascotaDetailsViewModel → Detalle
MascotaDropdownViewModel → Selects

BaseController

Controlador base que provee funcionalidad compartida: alertas, respuestas AJAX estandarizadas e ID del usuario actual.

public class BaseController : Controller
{
  int CurrentUserId { get; }
  void ShowAlert(text, type);
  JsonResult AjaxResult(model, success);
}

Dependency Injection

Todos los servicios y repositorios se registran en ServiceConfiguration.cs vía extension methods.

Soft Delete

Eliminación lógica con campo EsEliminado. Los registros nunca se borran físicamente.

Audit Trail

Todas las entidades registran UsuarioCrea, FechaCrea, UsuarioModifica, FechaModifica.
